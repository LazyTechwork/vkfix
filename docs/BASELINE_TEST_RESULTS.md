## ❌ Что НЕ работает

### 1. Переключение раскладки (1/3 тестов) ⚠️

**Прошло**:
- ✅ `rjn` → находит "кот" (работает!)

**Провалено**:
- ❌ `ghbdtn` → НЕ находит "привет" (стикера нет в тестовом наборе)
- ❌ `cj,frf` → НЕ находит "собака" (проблема с запятой в раскладке)

**Анализ**:
```
"rjn" → переключается в "кот" → [id: 1, 3] ✅
"ghbdtn" → переключается в "привет" → [] (стикера нет)
"cj,frf" → переключается в "со?ака" → [] (запятая не обрабатывается)
```

**Проблема**: Функция `switchKeyboardLayout` не обрабатывает запятую `,` → `б`. Это баг в моке, но может быть и в реальной функции.

**Рекомендация**: 
1. Проверить реальную функцию `switchKeyboardLayout`
2. Добавить обработку всех спецсимволов клавиатуры
3. Добавить тесты для всех символов раскладки

## 🔍 Интересные находки

### 1. Опечатка "кофф" находит "кофе"! 🤔

```
Опечатка "кто" вместо "кот" → [] ❌
Опечатка "сабака" вместо "собака" → [] ❌
Опечатка "кофф" вместо "кофе" → [id: 7] ✅ (неожиданно!)
```

**Анализ**: Почему "кофф" находит "кофе"?
- Возможно, префиксный поиск: "коф" совпадает с началом "кофе"
- Или семантическая карта содержит "кофф" как синоним?

**Вывод**: Случайное частичное совпадение, но не настоящий fuzzy matching.

### 2. Количество результатов растет с количеством слов

```
1 слово ("кот"): 2 результата
2 слова ("кот собака"): 3 результата
3 слова ("кот собака чай"): 4 результата
```

**Анализ**: Чем больше слов, тем больше результатов, т.к. каждое слово добавляет свои стикеры.

**Вопрос**: Это хорошо или плохо? 
- ✅ Хорошо: больше вариантов для пользователя
- ❌ Плохо: может быть слишком много нерелевантных результатов

### 3. Для 100 стикеров с одним словом возвращается только 2 результата

```
100 стикеров с "Кот 0", "Кот 1", ..., "Кот 99"
Запрос "кот" → только 2 результата
```

**Анализ**: Возможно, слишком строгий minScore или ограничение maxResults применяется раньше.

**Рекомендация**: Проверить логику фильтрации по minScore.
