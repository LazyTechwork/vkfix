# Исправление семантического поиска

## Проблема
Семантический поиск не работал в реальном использовании: запрос "кек" не находил стикеры со словом "смех", хотя они находятся в одной группе синонимов в семантической карте.

## Причина
Проблема была в функции `calculateMatchRatio` в `SearchEngine.ts`. Она вычисляла коэффициент совпадения слов запроса, но **не учитывала семантические связи**.

### Как это работало раньше:
1. Пользователь пишет "кек"
2. Семантический поиск находит синонимы: "смех", "ржач", "хахаха" и т.д.
3. Находятся стикеры с этими словами
4. **НО**: `calculateMatchRatio` сравнивал слово "кек" из запроса со словом "смех" из стикера
5. Совпадения не было → `matchRatio = 0`
6. `finalScore = baseScore * (0.25 + 0 * 0.75) = baseScore * 0.25 = 0.175`
7. `minScore = 0.3` → результат отфильтровывался

## Решение
Добавлена проверка семантических связей в функцию `calculateMatchRatio`:

```typescript
// Проверяем семантические совпадения
const synonyms = this.index!.semanticMap.get(queryWord) || new Set();
for (const matchedWord of matchedWords) {
  if (synonyms.has(matchedWord)) {
    matches += 0.9; // Семантическое совпадение почти как точное
    break;
  }
}
```

### Как это работает теперь:
1. Пользователь пишет "кек"
2. Семантический поиск находит синонимы и стикеры
3. `calculateMatchRatio` проверяет: "смех" есть в синонимах "кек"? → Да!
4. `matchRatio = 0.9` (почти как точное совпадение)
5. `finalScore = 0.7 * (0.25 + 0.9 * 0.75) = 0.7 * 0.925 = 0.65`
6. `minScore = 0.3` → результат проходит! ✅

  - Метод `searchSemanticMatches` - убрано условие `if (!candidateStickers.has(sticker))`
